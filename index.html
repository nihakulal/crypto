Homophonic Substitution Cipher

Explore how multiple ciphertext symbols can hide the frequency patterns of common letters.

Traditional substitution ciphers use one symbol for each letter. This makes common letters such as E and T easy to identify using frequency analysis.

A homophonic substitution cipher solves this problem by giving frequently occurring letters multiple possible ciphertext symbols.

Theory & Concept

Why ordinary substitution is vulnerable

If E always becomes the same symbol, an attacker can count how often that symbol appears and guess that it represents E.

Normal substitution: E E E E E E E ↓ ↓ ↓ ↓ ↓ ↓ ↓ X X X X X X X → Reveals an obvious frequency pattern.
How homophonic substitution helps

E is given multiple codes (19, 20, 21). The same plaintext can produce different ciphertexts:

Example plaintext: MEET Possible encryption 1: 35 20 20 50 Possible encryption 2: 35 21 19 51 → The same plaintext produces different ciphertexts.
Frequency Class Allocation

Frequent letters receive more codes so their ciphertext occurrences are distributed across multiple symbols.

Cipher Algorithm

Encryption
  1. 1 Convert text to uppercase.
  2. 2 Read each character.
  3. 3 Find its available homophones.
  4. 4 Randomly select one code.
  5. 5 Add the code to ciphertext.
  6. 6 Preserve spaces using /.
Decryption
  1. 1 Read ciphertext codes.
  2. 2 Find each code in the reverse map.
  3. 3 Convert code to its letter.
  4. 4 Restore spaces where / appears.
  5. 5 Display plaintext.

Security Limitation
Homophonic substitution makes simple single-letter frequency analysis harder, but it is still a classical cipher and can be attacked using larger statistical patterns such as digraphs and trigraphs.

Experiment Result

The Homophonic Substitution Cipher was successfully implemented. The experiment demonstrates randomized encryption, multiple ciphertext representations for common letters, and deterministic decryption using a reverse mapping.
